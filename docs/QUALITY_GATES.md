# БАЗА. Русский язык — обязательные контрольные точки качества

Утверждённое направление: крупные содержательные релизы, глубокие промежуточные аудиты. Не считать число уроков, объём текста или число прошедших тестов доказательством качества. Внутренняя проверка ИИ не является независимой филологической экспертизой.

## Цикл каждого крупного этапа

1. **До написания:** матрица утверждённой программы: темы, подтемы, наблюдаемые цели, предпосылки, проверяемые источники, требуемые виды практики, контроль и границы. Два урока на модуль не являются обязательным шаблоном. Не сокращать программу ради количества модулей.
2. **Внутри этапа:** сверить первую содержательную группу, затем каждый завершённый раздел. По каждой норме и ключу указать конкретное правило/словарную статью, дату доступа и статус (норма, вариант, классификация, стилистический выбор). Если источник не удалось открыть, зафиксировать ограничение. Перепроверка всех новых и изменённых оцениваемых заданий, включая неверные варианты; повторно решать задания до просмотра ключа. При неоднозначности задать контекст, принимать обоснованные варианты либо вывести из автоматического оценивания.
3. **Перед упаковкой:** сверить 100% новой и изменённой теории, практики, карточек, экзаменов, объяснений и кейсов с матрицей; устранить выявленные блокеры; проверить старый функционал, прогресс и PWA. Запустить `node scripts/audit-quality.mjs`, `npm test`, `npm run pwa:build`, затем снова тесты и проверить архив. Строгий режим `node scripts/audit-quality.mjs --strict` проверяет позиции ключа в авторском порядке показа (`displayOrder`, при отсутствии — порядок массива) и точные повторы заданий, включая варианты выбора и классификацию. Перекос канонических индексов выводится отдельным диагностическим полем; индексы хранятся для совместимости истории. Это машинные сигналы, не замена аудита. Отдельно провести браузерные сценарии, если доступна среда. Не выдавать имитацию DOM/IndexedDB/SW за реальный браузер.
4. **Локальная приёмка владельцем:** один архив на крупный этап, резервная копия, запуск, краткие сценарии, по одной команде PowerShell. Не просить владельца вручную просматривать сотни заданий. Если выявлен блокер, исправить в том же этапе, не переходить дальше. Подтвердить GitHub после отправки.

## Журнал аудита

Для каждого замечания: ID, релиз, путь/ID урока или сценарий, фактическое наблюдение, воспроизведение, источник/основание, серьёзность, способ исправления, повторная проверка и состояние. Статусы: открыто, исправлено и перепроверено, отложено с обоснованием, не проверено. P0 — потеря данных/недоступность/безопасность; P1 — неверная норма или оценивание, разрушенная методика, ключевой сценарий; P2 — существенный недостаток полноты/UX; P3 — улучшение. Открытые P0/P1 блокируют переход к следующей крупной партии; ограничения среды не маскировать успешным тестом. Для частной рабочей сборки явно обозначить непроверенные сценарии. Публичный выпуск блокируется отсутствием независимой филологической и реальной браузерной/мобильной приёмки.
