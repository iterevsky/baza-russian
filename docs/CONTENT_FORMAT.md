# Формат учебных материалов v1

`content/catalog.json` содержит `schemaVersion`, `courseId`, массив разделов (`id`, `title`, `moduleCount`, `description`, `lessons` с ID, относительным JSON-файлом и статусом). `content/tips.json` содержит самостоятельные языковые хитрости. `content/lessons/introductory-words.json` — первый образец урока: стабильные ID урока, модуля, раздела и элементов, версия, цели, связи, источник, контекст ИИ, теория, практика, карточки, контроль. Статус `draft` не равен опубликованному уроку.

Поддерживаемые блоки теории: heading, paragraph, rule, example, steps, examples, tip, deep. Только данные, никаких HTML/JS в текстах. Текст экранирует шаблон. Контроль: exact-text, практика: comma-positions. Форматы проверяет `src/core/content.js`; после каждого изменения `npm test`. Загрузчик читает JSON по HTTP и проверяет соответствие каталогу. Не изменять ID опубликованного элемента; при изменении смысла или эталона повышать версию. В v0.6.0 два урока в каталоге; история сопоставляется по стабильным ID, прежние индексы мигрируют только в исходный урок. Загрузчик проверяет уникальность ID элементов курса и существование связей. Прогресс schema 2 содержит тему оформления, избранное, активный урок и byLesson с попытками, отметками карточек, экзаменами и конспектом. Импорт schema 1 и 2 поддерживает совместимые записи, несовместимые записи импорта отклоняются. Порядок и смысл существующих заданий нельзя менять без разработки версионной миграции; не менять ID. Регулируемый порог, независимые проверочные серии и нормативная приёмка остаются следующими этапами.

## Дополнения v0.7.0 (обратно совместимые)

- `exam` остаётся вариантом A. Необязательный `examVariants` — массив дополнительных вариантов с тем же форматом (`id`, `version`, `threshold`, `questions`). У каждого варианта и задания отдельный ID. Тексты контрольных предложений не должны повторяться между вариантами или в практике расстановки запятых. Старые ID и порядок не изменены.
- `practice` поддерживает `single-choice`: `id`, `type`, `prompt`, `options` (массив строк), `expected` (массив с единственным индексом правильного варианта), `ex`. В истории `selected` содержит индекс выбранного ответа. Новый тип добавляется после старых заданий.
- Схема прогресса 2: необязательный `examDraft` в данных урока (`examId`, `version`, `index`, `answers`) сохраняет незавершённую попытку. Завершённые варианты идентифицируются по `examId`; результаты прежнего A сохраняются. Импорт проверяет совместимость истории и черновиков.


## Расширение v0.8

`multi-choice`: те же поля, что в `single-choice`, но `expected` содержит минимум два уникальных индекса и не все варианты. Оценка требует точного множества выбранных ответов. Существующие ID не меняются. В схеме прогресса 2 добавлено `masteryThreshold` (50–100, шаг 5, по умолчанию 100) и `threshold` в черновике и результате экзамена. Старые записи получают 100. Оценки неизменны; статус освоения вычисляется по текущему порогу, результат отдельной проверки — по сохранённому. Поле `threshold: 100` в учебном JSON остаётся исходным критерием формата v1.

## Отдельный модульный контроль (v0.12)

`catalog.modules` — необязательный массив ссылок `{id,file}` на `modules/*.json`. Модуль v1 содержит `id`, `title`, `moduleNumber`, `status: draft`, `lessonIds`, `source`, `variants`. Каждый вариант содержит стабильные `id`, `version`, `questions`. В текущем контракте два или более вариантов, ровно два задания `exact-text` на каждый урок модуля, с `id`, `lessonId`, `raw`, `answer`, `ex` и необязательной `instruction`. Проверяются соответствие уроков, уникальность ID и новых предложений относительно пунктуационной практики и экзаменов, равномерность покрытия. Ответ должен отличаться от исходного предложения только запятыми и нормализуемыми пробелами.

Схема экспорта 2 дополнена `byModule[moduleId] = {exams, draft}`. Результаты содержат версию варианта, идентификаторы заданий, ответы, балл, дату и сохранённый порог; черновик хранит ответы и порог. Несовместимые записи модуля блокируют импорт. Старый экспорт без `byModule` поддерживается. Новые результаты не следует импортировать в старый код.

## Расширение практики v0.13

`classification`: `id`, `type`, `prompt`, `rows`, `categories`, `expected`, `ex`. Индекс выбора = индекс строки × число категорий + индекс категории (с нуля). Ровно один индекс на строку, в эталоне порядок строк фиксирован.

`text-edit`: `id`, `type`, `prompt`, `raw`, `accepted` (непустой массив допустимых исправленных текстов), `ex`. Только изменение запятых и нормализуемых пробелов. Проверка по NFC и нормализации пробелов, регистр и прочие знаки значимы. Не свободная редактура. Попытка хранит `selected: []` и `answerText`; классификация хранит выбранные индексы в `selected`. При импорте проверяются полнота и соответствие оценки эталону для новых типов. Прежние ID и версии не изменены, новые элементы добавлены в конец практики.

## Углублённые разборы и открытые кейсы (v0.14)

Необязательное поле `deepDive`: массив объектов `{title, text, examples}`, `examples` — не менее двух пар `[label, example]`. Разборы раскрываются вместе с блоком `deep`.

Необязательное поле `editorialCases`: массив объектов `{id, title, task, model, criteria}`, где `criteria` — минимум две непустые строки; ID начинается с ID урока и `.editorial.`. Не смешивать с `practice`, `exam`, `examVariants`. Образец — возможный ход рассуждения, а не единственный эталон. Свободный текст не оценивается и не входит в статистику, экспорт или AI-контекст. Сессионные черновики изолированы по ID, сбрасываются при импорте или перезагрузке.

Источники для сверки новых авторских примеров: академический справочник (§§ 91–95), https://orthographia.ru/punctuatio.php?sid=126 и https://orthographia.ru/punctuatio.php?sid=127 ; справочник Грамоты.ру: https://gramota.ru/biblioteka/spravochniki/spravochnik-po-punktuatsii/prilozhenie-2-vvodnye-slova-i-sochetaniya . Полная редакторская проверка всех материалов отложена до v0.15.

## Редакторская сверка (v0.15)

Статусы урока и модуля: `draft`, `reviewed`, `published`. `reviewed` обозначает внутреннюю редакторскую сверку, а не внешнюю сертификацию. Статус ссылки в каталоге должен совпадать со статусом урока. Редакционные уточнения без изменения ключей не требуют смены версии данных; изменение правильных ответов требует отдельной стратегии миграции. См. `docs/EDITORIAL_REVIEW_07_08.md`.

### План программы (v0.16.0)

Каждый раздел каталога содержит `plan`: упорядоченный массив объектов `number` (NN.NN) и `title` с количеством записей `moduleCount`. Урок связывается с планом через `sectionId` и `moduleNumber`. Существующий `moduleId` связывает урок с паспортом модуля и его контролем; модуль без общего контроля может иметь уроки, но не запись в `catalog.modules`. Не переставлять старые уроки в исходном массиве ради отображения: порядок плана используется только в интерфейсе, а legacy-импорт опирается на первый урок. Запланированные темы не получают учебный прогресс или фиктивные оценки.

## Расширенная пунктуация экзаменов (v0.17.0)

Необязательное поле `marks: "comma-colon-dash"` у `exact-text` (в уроке или модульном контроле). При его наличии эталон меняет только запятые, двоеточия, тире и пробелы; исходное предложение не содержит этих знаков. Слова, регистр, Ё/Е, внутрисловные дефисы и конечный знак остаются значимыми. Нормализация дополнительно учитывает пробелы вокруг двоеточия и принимает дефис или короткое тире с пробелами как способ ввода длинного тире. Урок объясняет правильный печатный знак. Это не проверка типографики. Без поля `marks` используется прежняя проверка. Нельзя добавлять поле к уже выпущенному заданию без отдельной проверки совместимости результатов. Для неоднозначных конструкций явно задавайте нейтральное прочтение и исключайте альтернативные авторские схемы из автоматического контроля. Модульный контроль динамически использует число уроков, по два задания на тему в каждом варианте.

### v0.18: расширение охвата модуля
Вариант может иметь `lessonIds` (непустой уникальный поднабор `module.lessonIds`). Старые варианты сохраняют исходный охват и вопросы. Новые варианты без этого поля покрывают весь модуль. Должно быть как минимум два полных варианта; два задания на урок в каждом варианте его охвата. Новые попытки используют только полный охват; архивные черновики можно закончить. Историческая оценка не подтверждает освоение добавленных тем. `marks: "comma-parentheses"` разрешает проверку запятых и парных круглых скобок, но не подмену тире; сырой текст без этих знаков, эталон с парными скобками, условие явно задаёт оформление скобками. Конечные знаки и слова сохраняются.

### Рабочий индекс v0.19.0
`content/runtime-index.json` — автоматически генерируемый файл, не редактировать вручную. `npm.cmd run pwa:build` сначала валидирует полный курс, затем создаёт индекс без полей theory, deepDive и editorialCases, затем пересчитывает хеши автономного пакета. Полный файл урока при загрузке проверяется и сопоставляется с индексом.

## v0.20.0

Необязательное поле каталога `lessonOrder` содержит все ID уроков ровно по одному разу. Оно определяет порядок рабочего индекса и сохраняет прежний порядок миграции; разделы и модули отображаются в порядке программы. Новые ID добавлять в конец. Для уроковых и модульных экзаменов добавлен `grammar-answer`: `id`, `type`, `raw` (предложение), `instruction` (однозначный формат ответа), `answer`, `ex`; для модульного задания также `lessonId`. Без поля `marks`. Нормализация только NFC, пробелы, регистр. Порядок слов, ё/е и содержание учитываются. Не использовать для открытой редактуры или неоднозначного научного разбора. Старый exact-text не меняется.

## v0.27.0 — письменные ответы

Практика: `type: "text-edit", scope: "written"`, `prompt`, `raw`, `accepted` (список допустимых строк), `ex`. Контроль урока и модуля: `type: "written-answer"`, `instruction`, `raw`, `answer`, `ex`. Unicode NFC и обрезка внешних пробелов; регистр, Ё/Е, внутренние пробелы, дефисы и прочие знаки различаются. Не применять старую нормализацию запятых или грамматического ответа. Если допустимы несколько письменных решений в экзамене, уточнить условие или отнести к открытым кейсам; текущий формат экзамена содержит единственный эталон. Для карточек выбора сохраняются исходные индексы, перемешивается только представление.

## v0.28.0

Необязательное `stressWord` для `text-edit` со `scope: written`: русское слово без знака ударения; `accepted` содержит единственную строку-номер гласной от 1 до числа гласных. Кнопки отображают гласные в исходном порядке. Запись истории — прежнее поле `answerText`. Этот режим не предназначен для вариантных ударений или акустической оценки. Экзамены используют `written-answer` с явно заданным форматом. `sourceLinks` — необязательный массив объектов title/url (HTTPS), дополнительные ссылки урока.


## Совместимый порядок показа и история примера (v0.44)

Для single-choice необязательный `displayOrder` задаёт перестановку всех канонических индексов массива `options`, не меняя `expected`. Случайный показ строится на этой перестановке, сохранённые ответы используют исходные индексы. Машинный аудит учитывает авторский порядок показа и отдельно выводит канонический перекос. Для одной заменённой задачи с запятыми сохраняются `previousParts`, `previousEx` и `revision: 2`; новые ответы получают `questionRevision: 2`, прежние отображают исторический пример. Число позиций и ключ неизменны. Это узкая совместимая замена, не универсальный механизм версионирования заданий.
