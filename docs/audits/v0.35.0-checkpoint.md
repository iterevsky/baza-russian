# БАЗА. v0.35.0 — образовательное ядро и сохранение работ

Частная черновая сборка. Публичный выпуск не разрешён. Учебная программа: 107/107 модулей, 139 уроков, 773 практических и 2248 экзаменационных заданий, 145 редакторских кейсов. Все 246 исходных файлов уроков и банков идентичны v0.34.0. Изменения касаются механизма, а не содержания.

## Изменения и решения

- Редакторские работы сохраняются по стабильному ID кейса в `byLesson[id].editorialDrafts` в схеме 2. В рабочем индексе теперь есть только идентификаторы кейсов, а не их полные тексты. Старый экспорт без поля мигрирует с пустым словарём. Неизвестные ID, чужие кейсы и нестроковые значения отклоняются при импорте. Запись проходит через существующую очередь снимков. Тексты входят в экспорт; автоматически в ИИ не передаются. Открытые ответы не оцениваются автоматически. Ранее потерянные черновики восстановить невозможно.
- Для новых вопросов `grammar-answer` предусмотрена явная политика `semantic-v1` и список `accepted`. Учитываются только заранее указанные равнозначные ответы, NFC, регистр и пробелы; нет эвристической оценки по смыслу. Не применяется к орфографии и пунктуации. Старые ключи и результаты не изменены; новые правила нужно включать в новых вариантах с новыми ID, не править ключи завершённых вариантов. Реестр содержательно допустимых ответов ещё предстоит составить. Механизм версионирования контента не является автоматической миграцией произвольно изменённых старых вопросов.
- Уроки поддерживают `questionCount` (минимум 6, по умолчанию 6), модульные варианты — `questionsPerLesson` (минимум 2, по умолчанию 2). Валидатор сохраняет контроль уникальных ID, непересечения текстов и равномерности охвата. Поле `archived:true` исключает вариант из выдачи новых экзаменов и (для уроков) из текущего статуса освоения, но сохраняет историю и ключ для проверки старого экспорта. Уже начатый архивный черновик можно завершить. Необходимы не менее двух действующих вариантов модуля с полным охватом. Размеры новых банков не расширены в этой версии: синтетические примеры только в тестах.
- После завершения экзамена урока или модуля доступна отдельная повторная тренировка по ошибочным заданиям (после безошибочного результата — по всему раскрытому варианту). Эталон показывается после проверки. Эта тренировка не изменяет оценки и статус освоения, не расходует независимые варианты; её ответы не сохраняются после выхода/перезагрузки. Повторять известный вопрос как новый независимый экзамен запрещено. Для реальной повторной диагностики после исчерпания банка нужно добавить новые задания.
- Резервное localStorage: запись под общим Web Lock с проверкой исходного снимка и отметки миграции в IndexedDB; открытие/миграция также под тем же lock, если он доступен. Если другой экземпляр уже сохранил данные, старая вкладка получает ошибку и может экспортировать свой снимок. Без Web Locks резервный режим не пишет данные, показывает предупреждение; доступен экспорт. Это намеренное предпочтение сохранности данных перед доступностью записи. Защита рассчитана на вкладки новой версии на одном origin; старые версии и сторонние записи не используют этот lock. В IndexedDB остаётся транзакционный compare-and-swap.

## Контроль качества

118/118 Node-тестов, 8 новых тестов и расширенный controller smoke на mock DOM. Проверены 145 кейсов при импорте через ленивый индекс, старые ключи (3021), сохранение истории, отказ от повреждённых редакторских записей, политика допустимых ответов, новые размеры банков, архивирование, повторение урока и модуля, резервная запись при конфликте, режим без locks. Все 246 учебных файлов побайтово совпадают с базой. PWA: 273 ресурса. `npm run audit` проходит, `node scripts/audit-quality.mjs --strict` возвращает 1 из-за шести прежних банков с предсказуемыми исходными позициями. Аудит не отключён.

Реальный браузер, Web Locks, IndexedDB и офлайн в мобильном браузере не подтверждены (в этой версии реальный браузер не запускался; предыдущая приёмка была заблокирована средой). Тесты используют подмены интерфейсов. Независимая филологическая экспертиза и постатейная проверка не проведены.

## Локальная приёмка

1. Экспортировать прогресс, закрыть все вкладки старой версии, остановить сервер и распаковать поверх существующего Git-проекта. Не удалять данные браузера. Запустить `npm.cmd test` (118/118), `npm.cmd run audit`, `start.bat` (команда в PowerShell: `.\start.bat`).
2. Открыть редакторский кейс, записать текст, обновить страницу, переключить урок, экспортировать и проверить наличие `editorialDrafts`. Импорт тестировать на копии прогресса. Убедиться, что прежние оценки сохранены.
3. Завершить учебный и модульный варианты, открыть «Повторить раскрытые задания», проверить, что после тренировки количество экзаменов не изменилось. В двух вкладках проверить уведомление о конфликте и экспорт незаписанных изменений. Не удалять рабочие данные для имитации сбоя; использовать отдельный тестовый профиль браузера.
4. Проверить ширины 320/390/768/1440 px, светлую/тёмную темы, обновление PWA и работу без сети. После локальной приёмки commit/push.
