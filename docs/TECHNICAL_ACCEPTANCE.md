# Локальная техническая приёмка v0.46.0

Сначала экспортируйте прогресс из профиля, сохраните файл вне папки проекта. Для проверки используйте несекретный тестовый текст. Не очищайте данные сайта, IndexedDB или Cache Storage. Приложение всегда открывайте по прежнему адресу `http://localhost:8001/`.

## 1. Запуск и обновление
- Закрыть вкладки и PWA-окна, остановить старый сервер. Распаковать v0.46.0 поверх v0.45.0, сохранив `.git`.
- Выполнить `npm.cmd test` (155/155), `npm.cmd run audit`, `node scripts/audit-quality.mjs --strict`. Затем `.\start.bat`.
- В терминале должно быть `node scripts/serve.mjs` вместо `npx ...`. Сайт открывается без установки пакетов. При занятом порте определить процесс, не завершать незнакомый процесс автоматически.
- Дождаться готовности автономного пакета. Если показана предыдущая версия, дождаться «Обновление готово», закрыть все вкладки и окна и открыть снова. Проверить номер 0.46 в интерфейсе.

## 2. Сценарии приёмки
| ID | Действие | Ожидаемый результат |
|---|---|---|
| B01 | Открыть главную, каталог, урок, практику, память, хитрости и профиль; открыть глубокую теорию | Все экраны работают, нет пустого экрана и неожиданных JS-ошибок |
| B02 | Ввести уникальный тестовый конспект и редакторский черновик, дождаться сохранения, перезагрузить | Оба текста восстановлены |
| B03 | Открыть две вкладки одной версии; в первой внести изменение, во второй внести другое | Устаревшая вкладка не перезаписывает новое состояние; появляется предупреждение с возможностью экспортировать изменения. После теста закрыть устаревшую вкладку, не импортировать её поверх новой без сверки |
| B04 | Начать модульный экзамен, заполнить один ответ, закрыть и вновь открыть | Черновик возобновляется; проверка не выставляет оценку за незавершённый экзамен |
| B05 | Экспортировать прогресс, проверить наличие JSON; импортировать собственный свежий экспорт | Конспекты, черновики и результаты сохранены. Повреждённый импорт следует испытывать только в отдельном тестовом профиле |
| B06 | После готовности PWA перезагрузить страницу с активным service worker, остановить сервер, отключить интернет (или включить offline в DevTools), перезагрузить | Главная, ранее не открытый урок, практика и сохранение доступны. Снова включить сеть/сервер; не снимать регистрацию SW и не удалять кеш |
| B07 | В DevTools Responsive проверить 320, 360, 390, 768, 1024 и 1440 CSS px, светлую/тёмную тему и длинный урок | Нет горизонтального скролла и перекрытых кнопок, текст читаем, нижняя навигация не закрывает последний элемент |
| B08 | Tab/Shift+Tab/Enter/Space: навигация, выбор ответа, обратная связь, следующая карточка, поле экзамена | Видимый фокус, доступность контролов, не происходит потери фокуса после перерисовки |
| B09 | Открыть печать урока/карточек, проверить ИИ-копирование, отменить печать | В печати нет лишней навигации; копирование либо работает, либо предлагает ручное |
| B10 | Открыть DevTools Network, проверить запрос runtime-index.json с gzip; Performance при холодном запуске, без очистки прогресса | Записать размер передачи, время до видимой главной, ошибки. Для холодного запуска использовать отдельный чистый браузерный профиль, не основной |

Для проверки горизонтального скролла можно выполнить в консоли DevTools на каждом экране:

```js
({viewport: document.documentElement.clientWidth, content: document.documentElement.scrollWidth, overflow: document.documentElement.scrollWidth > document.documentElement.clientWidth})
```

`overflow: false` — ожидаемый результат, но визуальная проверка всё равно нужна. При ошибке запишите экран, ширину, браузер и текст сообщения. Для финальной приёмки нужны фактические результаты B01–B10; Node-тесты их не заменяют. На реальном смартфоне дополнительно проверить touch, safe-area, поворот/клавиатуру и автономный режим при доступном HTTPS-хостинге либо установленной PWA; мобильная эмуляция на ПК не равна проверке устройства.
